# Обогащение карточек товаров техническими характеристиками — статус

Дата: 2026-09-11 (сессия продолжается)

## Задача

578 карточек товаров (content/products/*.json) уже рендерят таблицу
«Характеристики и совместимость» из поля `specs` (см.
`src/app/catalog/[...slug]/page.tsx`), но само поле почти везде содержало
только 5 шаблонных строк (Производитель/Артикул/Тип/Состояние/Наличие) —
реальных технических параметров там не было. Цель — заполнить `specs`
настоящими характеристиками, не привлекая ручной труд.

## Ключевое открытие

560 из 578 товаров — Renishaw. Из них у **417+** в поле `description` уже
записан родной код заказа Renishaw (например
`M3 STY D4R L50 EWL46 d2TC`) плюс частичный русский перевод материала
шарика/стержня. То есть для большей части каталога данные уже есть на
сайте — их не нужно искать в интернете, только вычленить из текста и
переложить в структурированную таблицу. Настоящий интернет-research
нужен только для «умных» позиций (щупы-передатчики, интерфейсы, приборы
калибровки), где в описании — связный текст, а не код заказа.

## Сделано

### Уровень 1+2 — детерминированный парсинг существующих описаний (без интернета)

Скрипт разобрал код заказа в описании и добавил в `specs`:
`Резьба`, `Диаметр шарика/наконечника`, `Материал шарика/наконечника`,
`Материал стержня` (из уже готового русского текста) и
`Общая длина (L)`, `Рабочая длина (EWL)`, `Диаметр стержня`,
`Толщина диска` (из самого кода).

**Результат: 469 товаров обогащено.** Один товар (A-5004-7604) с
неоднозначным составным кодом (`L8SS SWIVEL L10` — два разных участка
длины) сознательно оставлен без поля длины, а не угадан.

Проверка: `npm run check:products` проходит; вручную сверено ~15 карточек
по всем категориям (щупы, дисковые щупы, удлинители, калибровочные сферы,
болты, шарниры). В процессе найдены и исправлены 2 собственные ошибки
парсинга до публикации:
- лишняя точка на конце значения «Резьба»;
- дробные диаметры стержня обрезались до целого, когда сразу после числа
  шёл буквенный код материала без пробела (`d3.8CE` читалось как 3, а не
  3.8) — пересчитано и точечно исправлено 131 значение.

Рендеринг проверен вживую (`next dev` + curl) на двух карточках — новые
строки в таблице отображаются корректно.

## Осталось (план продолжения, без дальнейших вопросов с моей стороны)

**91 позиция Renishaw** — «умные» семейства и часть щупов в другой
нотации: RMP40/60/400/600 (и M/QE варианты), OMP40/60/600 (и
M/LS/legacy варианты), OLP40, RLP40, RTS, TS20/27R/34, тул-сеттеры
NC4/NCPCB/TRS2, интерфейсы OMI/RMI/HSI/OSI, руки HPRA/HPPA/HPMA/HPGA,
системы LP2/LP2DD, комплекты EQUATOR, калибраторы XL-80/XM-60/XR20-W,
QC20 ballbar, и ~10 щупов с параметрами прямо в заголовке в нестандартном
формате. Продолжу так же, семьями (один official datasheet — на все
артикулы этой линейки), с указанием `specsSource` для каждого.

**18 товаров других брендов** (Heidenhain, SINO, Marposs, Fanuc, SMW-Autoblok,
ИЦ Станкосервис) — отдельный небольшой батч, официальные сайты
производителей.

Работа продолжается в этой же сессии без необходимости моего/вашего
дополнительного участия — принцип и проверки (schema-check, сверка с
источником, ручной QA выборки) те же, что и в этом отчёте.
