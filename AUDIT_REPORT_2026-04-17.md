# Аудит репозитория и сайта (2026-04-17)

## Что проверено
- Структура и кодовая база Next.js (App Router), компоненты, SEO-файлы, формы, поиск.
- Базовые проверки качества: `npm run lint`, `npm run build`.
- Проверка уязвимостей зависимостей: `npm audit --json`.

## Критичные и важные находки

### 1) Сборка падала из-за ошибок ESLint (исправлено)
**Проблема:** были неиспользуемые импорты `TrustBlock` в двух файлах, из-за чего `next build` завершался с ошибкой.

**Риск:** нельзя стабильно выпускать изменения и деплоить проект.

**Статус:** ✅ исправлено (импорты удалены).

---

### 2) Публичный ключ Web3Forms был захардкожен в клиентском коде (улучшено)
**Проблема:** `access_key` для Web3Forms хранился непосредственно в исходниках.

**Риск:** ключ становится частью Git-истории и сложнее ротация/управление через окружение.

**Статус:** ✅ улучшено — ключ переведен на `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY`.

**Что сделать в окружении:**
- Добавить переменную `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY` в `.env`/секреты хостинга.
- Проверить форму на проде после деплоя.

---

### 3) Логирование payload формы в консоль браузера (исправлено)
**Проблема:** в форме был `console.log` с персональными данными клиента.

**Риск:** утечка PII через консоль и сторонние лог-сборщики браузера.

**Статус:** ✅ исправлено — лог удален.

---

### 4) Уязвимости зависимостей (требуют обновления)
По `npm audit` обнаружены high severity:
- `next` уязвим в диапазоне `< 15.5.15` (DoS, advisory GHSA-q4gf-8mx6-v5v3).
- транзитивно `basic-ftp` (через дерево зависимостей).

**Рекомендации:**
1. Обновить `next` до версии с фиксом (`>= 15.5.15`).
2. Выполнить `npm audit fix`, затем повторно проверить `npm audit`.
3. Прогнать smoke-тесты UI и форм после обновления.

## Наблюдения по SEO и контенту
- `metadataBase`, `robots` и `sitemap` используют fallback `https://example.com`, если не задан `NEXT_PUBLIC_SITE_URL`.
- На проде обязательно задать корректный `NEXT_PUBLIC_SITE_URL`, иначе канонические URL/карта сайта могут указывать на `example.com`.

## План дальнейших улучшений
1. Поднять CI: блокирующие проверки `npm run lint` + `npm run build` + `npm audit --audit-level=high`.
2. Добавить простые e2e/smoke-тесты ключевых страниц и отправки форм.
3. Централизовать контактные данные (`info@example.ru`, телефон) в конфиге сайта.
4. Рассмотреть серверный прокси для отправки форм, если потребуется контроль антиспама, rate-limit и аудит событий.
